# Guide Coverage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Root implements sequentially; independently scoped read-only guide/entity researchers and one final fresh review support it.

**Goal:** Account for guide-listed content against native game data and repair demonstrated navigation omissions.

**Architecture:** An offline, provenance-bound audit joins guide topics to the complete native field census and current story/entity adapters. Runtime corrections stay at existing native presentation boundaries; private future/reward data never becomes a runtime target catalog.

**Tech Stack:** Existing Python field audit, C# net35 runtime/net8 fixtures, GameFAQs web sources, original Mono and transactional packaging.

**Spec:** docs/superpowers/specs/2026-11-01-guide-coverage-design.md

## Global Constraints

- Use ordinary visible information; no hidden names/rewards, guessed visual props, synthetic Confirm or changed native timing/control.
- Preserve saves, settings, unrelated game files and all608recordings.
- No gameplay/launcher input automation or game launch for offline evidence.
- Retain the canonical source checkout on a dedicated branch per the existing preference.

## Review Focus

- Guide heading matches and script presence must never masquerade as full runtime/live coverage.
- All native fields, guide story chapters and optional topics need explicit status and unresolved evidence.
- Visible native bubble provenance must retain the exact source object and expire with current presentation.
- Main-story checkpoints must not advance because a guide says an action occurs later.
- Optional objectives remain in ordinary categories and do not displace required Story targets.
