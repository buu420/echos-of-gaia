# Guide audit adapter validation

The November 1 changes use native presentation and state, independently of the
offline guide comparison. No walkthrough file is loaded by the game.

The core tests cover all five Pinnacle fragment masks, original script/player
fingerprints, the 160 Fossil Roo junction switch/component table rows and 384
platform switch/flower combinations, local boarding
flags, Gulug completion, unknown state, physical UID versus script SID, and
the absence of invented approaches. Native context fixtures compile the actual
bridge with controlled engine boundaries. The coat description requires the
rendered body; a hidden staff does not name a fragment.

The touch-confirmation cases check exact field/UID/script, the presented icon,
native selected region/facing, original byte buffer, idle or bounded queued
frame, competing NPC/region priority and the actual callback's readiness.
The adapter only reads these conditions. Native Confirm remains unchanged.

`PresentationIntegration.Tests` compiles the actual card reader, native card
formatting and button input handler. It checks visible face grades rather than
hidden growth precision, both board defenses, Triple Triad layout, hidden
arrows, first hand/board focus, cancellation, rematch and speech-output recovery.
It also compiles the numeric dialog adapter. The fixture checks parser and
generation identity, visibility/render readiness, rejected delivery, latest
digit/amount, lifecycle cleanup, and coalescing concurrent auction panels.
The opening-speech regression preserves adjustment/selection/Confirm/Cancel
instructions, queues the first snapshot, and coalesces automatic price changes
while the speech backend reports busy. Automatic price announcements remain
non-interrupting when that status is unavailable; later deliberate digit
changes retain immediate feedback.
Only the verified English templates are supported. Numeric input comes from
completed visible parsers, not the live message-variable buffer or inventory.

The emitted-assembly checks `--verify-interaction-cues` and
`--verify-guide-adapters` inspect the actual x86 and x64 game outputs without
executing game singletons. They require the production hooks and reject native
input/request/state writes or blocking file/thread work in the new readers.
The actual field2108 facing branch reads rotation without executing a script.

`guide_audit.py --check` verifies all 818 field records, 44 chapters, 364 Story
checkpoints, 23 optional topics and 87 exact native entry bindings. It rejects
lost records, changed source identities and manufactured full-accessibility or
live-proof claims. `compile_story_prerequisites.py --check` verifies that the
compiled table matches its reviewed metadata.

These are static and controlled-boundary checks. They do not prove actual
Unity rendering, physical-controller delivery, live NVDA speech, auction
timeliness, a complete puzzle sequence or an end-to-end accessible playthrough.
No game launch or gameplay input was used for this audit.
